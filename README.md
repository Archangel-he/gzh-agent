# Bloop · 公众号设计桌面 Agent

[许可：PolyForm Noncommercial 1.0.0](LICENSE) · 非商业用途按许可执行，商业使用须另行授权 · [许可范围与历史版本](NOTICE.md)

基于 DeepSeek Harness 0.2.1-rc.2 源码构建 macOS 桌面版本，另提供 Windows x64 源码启动版。启动后直接进入可输入的新对话，固定使用本项目目录，左侧平铺历史对话；公众号插件和设计技能随会话加载。保留内置的文件、搜索、子 Agent、附件、预览和文件交付功能，默认隐藏历史侧栏，鼠标靠近左边缘时展开。左下角设置按钮直接打开设置页，导航只显示通用和模型，通用里的 Permission 保留。

## 现在怎么运行

本机已经安装依赖并配置主模型。双击上级目录的 **Bloop.app** 即可打开修改后的桌面界面，已完成正常退出后由系统直接打开的冷启动验证。也可以双击 **启动Bloop.command**，或在此目录运行 `npm start`。这些入口均加载本项目的独立配置。上级目录的原版 `DeepSeek Harness.app` 提供本地运行环境，请保留。

macOS 应用直接从已签名的 Electron 主程序启动，主应用和辅助进程使用 Bloop 名称与独立标识；权限用途说明也使用 Bloop。继续使用原有 data 目录、历史与模型配置。系统可能为修正后的身份重新申请授权，旧 dsh 授权记录不会被自动清除。

打开后直接输入正文和设计要求，无需选择文件夹、启用公众号插件或指定技能名称。启动器默认关闭开发者工具的自动弹出。可以通过内置附件入口上传图片，也可指定项目目录内的 PNG、JPG、WebP 文件。当前每篇上限六张、单张 5 MB、正文 16000 字。一篇文章使用一个会话。首版应用重启后会打开新对话，旧对话仍保留在历史中；打开历史对话后，调用 gzh_prepare_article 会从持久工具记录恢复已有任务；也可指定 existing_directory。追加／替换图片使用 update_article_assets（工作区 image_path 或本轮聊天附件 image_index 二选一），保留原素材 ID、旧图片与成功稿，不需重新初始化。

示例请求：

> 把这段原文排成微信公众号文章，保留全文，使用墨绿与暖橙配色。配图使用 examples/walk-reference.png，先识别图片，不生图。完成后交付 HTML 和预览。

示例正文位于 `examples/示例原文.txt`；示例图片是程序绘制的测试素材，不是 AI 生图结果。

## Bloop 桌面交互

首次打开直接进入输入界面，无登录和首次引导。设置保留通用与模型，权限设置仍在通用中；界面、原生菜单与关于面板使用 Bloop 名称。模型页按用途分为设计模型（对话、策划与排版）、识图模型（图片理解，留空继承设计模型）和生图模型（独立图像接口）。每项分别保存，密钥留空保留原值，修改后退出并重新打开应用生效。技术性的 API 地址和模型 ID 保留真实值；第三方许可证和代码归属保留。

- 历史入口持续可见；鼠标接近左侧展开磨砂历史，复用原生背景层避免聊天文字穿透。
- 输入框下方不显示用量与详情。伙伴持续动画并响应实际运行、等待与失败状态；任务阶段不使用虚构百分比。
- 图片附件可选正文配图、风格参考或文字提取，已有文章可指定替换目标；发送前先保存用途记录。每篇最多六张、单张 5 MB。
- 文章成果卡提供预览、复制排版、保存 HTML 和版本选择。原生复制写入富文本和纯文本，不依赖预览网页的剪贴板权限。
- 预览可切换 390px 手机宽度和自适应宽度。手机宽度是近似排版，最终仍须检查公众号手机预览与图片上传结果。
- 新交付使用 revisions/vNNNN 固定快照；恢复旧版会另存新版本。旧交付卡明确标记为当前文件；早期 versions 备份缺少完整素材清单，因此只预览、不恢复。首次读取时只迁移一次，失败可就地重试。

## 实际流程

1. 主 Agent 已加载 `gzh-design` 全文，按用户需求调用 `gzh_prepare_article` 建立本会话任务。
2. 需要确认图片内容时，`inspect_images` 启动真实 Harness 子 Agent，并将图片字节作为多模态输入，返回识别与风格分析。
3. 主 Agent 根据原文和要求自主设计，以内联样式生成公众号正文。没有固定主题数量限制。
4. 用户允许生图且已配置图像服务时，`generate_image` 委派插图策划子 Agent，再请求实际图片生成 API，保存图片文件。
5. `submit_article` 检查正文覆盖、图片引用和主动内容，通过后保存文件。失败不会覆盖上次成功的正文；同一会话继续修改时会保存独立成功版本。
6. 内置 `present` 交付 submit_article 返回的固定版本正文与预览路径。

输出保存在工作区 `gzh-output/<任务ID>/`：

- `article.html`：图片内嵌、可独立打开的完整 HTML，正文样式内联。
- `preview.html`：图片内嵌的独立预览与富文本复制入口，在原生侧栏也能显示配图。
- `assets/`：用于继续编辑和版本恢复的实际 PNG 素材；交付 HTML 显示不依赖此目录。
- `job.json`、`vision.txt`、`submission.json`：原文、识别结果和设计说明。
- `revisions/`、`current.json`：完整固定版本及当前稿指针。
- `versions/`：升级前的旧稿备份，保留为只读预览。

复制到公众号后仍须检查图片：本地图片路径不会自动变成微信素材地址，本版不含登录、素材上传或自动发布。请在公众号后台上传配图，并做手机预览。

## 文章任务的耗时预算

启动器设置 `BLOOP_PERFORMANCE=1`，标准模式的压缩余量为 8192 token、摘要输出上限为 2048 token，一次压力检查只做一次摘要。对于当前 131072 上下文／16384 输出预留的模型，压缩触发点从 49152 调整到 104857 token。每次自动摘要尝试后，等上下文再增加一个余量预算才允许下一次；真正的提供方上下文溢出仍走一次恢复。正常压缩继续保留近期消息。

每个用户轮次重新计数，公众号工具执行层限制如下：

| 阶段 | 上限与停止条件 |
| --- | --- |
| 找素材 | 2 次 web_search、6 次 web_fetch；从首次联网开始共 90 秒，单次联网工具 15 秒（文章 Shell 和 job_output 等待也限 15 秒） |
| 下图片 | gzh_download_images 接收至多 12 个候选；并发 3、单图 10 秒／5MB、至多 3 次重定向、不自动重试，部分成功也会返回文件及编号联系表 |
| 看图与检查 | read_image 总计 8 次；首次成功 submit_article 后 Shell（bash / pwsh 合计）和 read_image 各最多 2 次，用于一次整页检查和一轮合并修复 |
| 工具与交付 | 处理工具 32 次；另保留最多 3 次 submit_article 和 present 交付。达到上限使用已有素材、交付上个成功稿并说明缺失；没有校验通过的文件不报完成 |

图片工具只接收公共 HTTP(S) 地址，校验解析后的目标并固定连接地址，重定向重新校验；不读取本机或私网。Shell 中常见的图片下载命令会被提示改用专用工具；此提示是工作预算约束，权限和安全隔离仍由 Harness 管理。普通非文章任务不启用这些文章预算。

素材更新以整批为单位提交：任一图片无效或在提交素材清单前取消时，清理本次暂存图片并保留原任务。替换保留 asset://ID 但另存新文件；旧正文和预览直到新 submit_article 成功才更新，旧版本引用的原图继续保留。Windows 的短暂文件占用只重试原子替换，最多10次、间隔50毫秒；持续失败保留旧文件并清理暂存文件。没有删除素材或跨工作区导入功能。

## 模型和密钥

`data/settings.json` 为本机私有配置，权限 0600，整个 `data/` 已被 Git 忽略。共享项目时使用无密钥的 `settings.example.json`，复制到 `data/settings.json` 后填写自己的凭据。

- `main`：主模型，当前为 DeepSeek `deepseek-flash`。
- `vision`：留空继承主模型，可另外指定支持视觉输入的兼容接口。
- `image`：独立生图服务的 `baseUrl`、`model`、`apiKey`。DeepSeek 主模型 API Key 不等于已配置生图服务。

生图端目前支持 OpenAI 兼容的 `POST <baseUrl>/images/generations`、1024×1024、`data[0].b64_json` 响应。仅返回 URL 的服务尚未接入。没有配置时会返回明确错误，不能以占位图冒充生成成功。

桌面配置保存在 `data/desktop-home/profiles/desktop/cordis.patch.yml`，首次启动时初始化，之后保留用户在插件和模型页面中的修改。默认加载主模型路由、公众号插件、设计技能和原有内置功能插件。额外会话日志上传被关闭，会话启动采用完全访问且无需逐项审批的默认权限。需要独立凭据、额外依赖或更宽权限的实验插件不随界面简化自动启用。修改模型路由后以原生模型设置为准；编辑业务插件代码后退出应用并重新启动。


## Bloop 界面

空白对话显示动态伙伴和十二组中英文问候之一；开始任务后，同一只伙伴以 1.3 秒的平移和缩放过渡移动到左上角，保留较大尺寸，持续循环十二种动作、形态、环绕轨迹和粒子效果。系统减少动态效果设置会暂停装饰动画。创建按钮英文为 New Task，中文为新对话。侧栏在鼠标进入左侧 56px 区域时展开，键盘聚焦也可打开。历史侧栏使用 56px 强模糊与 180% 饱和度的磨砂玻璃层，macOS 主内容区在浅色、深色模式下均可透出系统背景；系统开启减少透明度时恢复不透明填充。新对话按钮点击高度至少 46px，侧栏右侧保留 28px 悬停缓冲，离开后延迟 320ms 收起，返回会取消收起。侧栏控件在主内容之后渲染，避开原生标题拖动区域；鼠标仍在侧栏内部时，输入焦点变化不会收起侧栏。宠物常驻窗口覆盖层，切换历史对话保留动画时钟，不会再次从中央飞向角落。构建版本标识、原欢迎标题、Standard mode、Tools 和输入框权限按钮均已隐藏；会话标题、Chat/Trajectory 标签与右上角工具也不显示，默认完全访问，系统账户权限和文章校验仍生效。斜杠候选菜单已禁用，输入框不再提示斜杠指令；输入 `/` 保留原字符，`@` 引用和文件附件继续可用。

宠物代码来自 https://github.com/jeremy-prt/bloub ，保留 MIT 署名和许可证，副本位于 `third-party/bloub-LICENSE`；动画核心及准确来源版本保存在 Harness 的 `ui-conversation/src/client/bloop/` 中。新应用图标由同一 SVG 核心生成，无需下载外部素材。

## Windows x64 源码启动版

Windows 入口是仓库根目录的 `启动Bloop.cmd`。这是首次运行会构建环境的源码启动版，目前没有独立 EXE 安装包或代码签名。安装 Node.js 24 LTS、Git for Windows 后，将仓库解压到可写目录，双击该脚本。首次准备还需要 Python 3.12、Visual Studio 2022 Build Tools 的 C++ 桌面开发组件和 Windows SDK，以编译 Harness 的 Windows 原生模块。需要可访问 npm、GitHub、nodejs.org 等依赖下载源；完整内置运行环境首次下载和编译较大，请预留充足磁盘空间并保持联网。

脚本会安装业务依赖，拉取 `harness.json` 固定的源码版本，应用 `patches/bloop-harness.patch`，编译 Bloop 前端并准备 Windows Electron 与原生运行环境，再打开桌面窗口。后续同目录启动复用构建。目录移动时重新构建；构建失败保留日志，不会删除用户配置。已有旧补丁缓存不会被强行覆盖：升级源码包后若补丁检查不通过，先退出应用，将 data/harness-source 改名备份，再启动以重新准备；data/desktop-home 中的历史和 data/settings.json 不受影响。

Windows 私有配置、模型凭据、历史和编译缓存均在 `data/`，不提交到 Git。首次启动可在设置 → 模型中配置自己的服务；额外识图和生图服务仍可在 `data/settings.json` 配置。不要将 Mac 的 `data/` 或 `node_modules/` 复制到 Windows。

GitHub Actions 的 `Bloop Windows` 工作流在 Windows x64 上执行业务测试、原生构建和桌面窗口启动检查，通过后上传 `Bloop-Windows-x64-source`。该 ZIP 是无密钥源码启动包，不是预编译安装包；下载后仍需上述首次准备。工作流通过只证明构建和开窗，不等于 Windows 上真实模型对话、图片生成或公众号复制的端到端验收。

### Bloop 文章设计技能

公众号任务统一使用 `.agents/skills/gzh-design/SKILL.md`。初始化任务后，`gzh_design_reference` 只读取随应用分发的白名单参考：先读主题索引，选择刊读、温暖叙事、简报或校园主题，再按需读取公共组件、配图与审稿规则；不会把整个参考库塞入系统提示。桌面与 Web 原型共用同一入口，原型不具备的截图与文件交付能力会明确降级。

用户提供优秀推文截图或要求更强艺术处理时，读取 `visual_story`，明确封面、字体层次与章节视觉母题。默认以真实照片和整篇一致的文字层级建立风格；艺术字不默认混用。仅在用户选择该题图方向时，`gzh_create_design_asset` 可在本地生成原创植物纸感题图与分隔图，支持宋体、黑体、楷体搭配，以及空心描边和反白镂空；无需生图接口。复杂艺术字输出为内嵌 PNG，正文保留可编辑文字。设计图同样占用每篇六张素材额度，当前模板适合自然、校园类叙事，其他视觉方向仍需另行设计。

交付页面不再统一添加白底与20px内边距；整篇底色、文字区边距与通栏照片关系由正文内联section定义，让预览与复制正文使用同一布局。已有固定版本文件保持原样，恢复或重新导出时会采用当前页面容器。warm参考提供摄影开篇、章节、偏置纸框与短句组件，不需要配置生图接口。原型入口的历史主题色只作参考，不覆盖用户给出的风格。

新增设计在预算内检查最终保存的手机宽度预览，最多一轮修复。参考读取计入原32次工具预算，生图仍需用户允许；所有素材、原文校验和不可变版本保存规则保持生效。外部项目仅作为设计方法调研来源，本地新增指导与组件为 Bloop 编写，没有安装整套第三方技能或引入远端排版服务。

文章图片会保留安全的自定义内联样式，包括圆角、尺寸、间距、边框、阴影和 object-fit/object-position 显示裁切；未指定的部分补充响应式默认值。素材地址校验和危险 HTML/CSS 拦截仍生效。Bloop 预览保留不代表微信编辑器一定保留，发布前仍需后台与手机验证。

交付的 `article.html` 和 `preview.html` 固定内嵌真实图片，单独移动 HTML 不依赖旁边的 assets 文件夹；素材目录仍用于后续编辑、版本恢复和内容校验。生成时使用素材 ID，程序负责嵌入；继续修改时工具返回去除 base64 的素材引用版正文，避免图片编码耗尽上下文。Bloop 会话启动默认采用 `danger-full-access` + `never`，不逐项请求工具审批；系统账户权限和文章输入/HTML 校验仍生效。
