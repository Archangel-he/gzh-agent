# 主题索引与文章配方

用本文选择一个主题，再调用 gzh_design_reference 读取该主题和 components。图片、审稿分别用 images、review；不要连续读取全部参考。

| topic | 适用 | 配方 | 不适用 |
|---|---|---|---|
| editorial | 专业观点、人物访谈、一般深度长文 | 清楚的标题区 → 原文导语 → 稳定章节 → 少量引语/照片 → 原文结尾 | 不必强加报纸多列或装饰英文 |
| warm | 生活随笔、旅行、人物故事、温暖叙事 | 标题 → 原文开场 → 段落与照片交替 → 安静的原文结尾 | 公告、硬性步骤不宜过多抒情装饰 |
| brief | 技术教程、通知、知识整理、数据说明 | 标题 → 现有摘要/要点（无则省）→ 步骤/论点 → 表格或代码（确有需要）→ 原文结论 | 不把每段都变成卡片，不虚构结论 |
| campus | 用户要求的校园文艺、纪实抒情、自然气质 | 从现有 campus-literary 组件中选标题/章节/正文；仅使用与内容相关的装饰 | 技术与密集公告；不要默认塞英文、极小字或章节序号 |

未指定风格时依据内容选择，混合文章按主要阅读任务决定；无明显偏向可采用 editorial。用户已有参考或明确风格优先，不能因精修擅自换主题。图片记录真实现场时，采用与照片协调的色板，不给照片覆盖“电影滤镜”或改造事实。

每篇先形成简短设计说明，记录到交付 notes：类型与读者；主题/用户覆盖；色彩角色；文字层级；组件和图片用途。此说明只指导本篇，不覆盖用户原始内容。选择可在一个短段落内完成，不需要额外调用模型或默认询问用户。

## 按需专题

- visual_story：用户提供优秀案例、要求较强视觉设计或认为当前稿不满意时优先读取；分析主视觉、同一视觉母题与图文节奏，可按所选方向创建原创题图/分隔图。

- components：正文、照片/图注、引语、列表和表格的可兼容片段。
- images：已有照片、参考图和生图的分工与简报。
- review：阅读节奏、移动端首屏和最终 HTML 审稿。
- title / poster：用户需要复杂标题卡或独立封面时。当前代码未提供其中所有高级渲染能力，不承诺未实现能力。
- structure：用户确有封面/首尾图/文章骨架需求时；骨架是可选配方，不能虚构官方首图、二维码或强制用户补齐所有段落。
- image_recipes：用户要求改造图片时参考；文档内的图生图配方并非当前工具能力，不按它假装完成图生图。
- constraints：排版被校验拒绝时定位规则。源码/实际工具结果优先于可能过时的行号和数量说明。
