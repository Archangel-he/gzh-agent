# 手机阅读审稿

HTML 校验通过是内容与安全的底线，视觉审稿检查的是实际阅读结果，不给自己编造“95分”。先审最终保存的 preview.html：图片路径、内联样式都已经经过清洗。默认看约390px的手机内容宽度；有条件兼看较窄约320px的断行，不扩大为多轮截图工程。

## 一次检查的六个问题

1. 首屏：能否清楚看见文章主题和阅读起点？标题是否被生硬拆字、挤成过多行？装饰是否把正文推出过远？
2. 层级：原标题、章节、正文、图注是否有清楚但克制的区别？相同角色是否一致？辅助字有没有小到难以读？
3. 节奏：段落连续可读，章节间距稳定，是否每段都包卡片或无意义居中？正文是否过密、留白是否断裂？
4. 图文：照片完整且比例正确，图片与所在段落有关；图注不贴脸、不悬空。未自定义时 img 默认18px上下间距，外层不要重复制造大空洞；自定义间距与圆角需在最终预览中检查。
5. 风格：是否符合用户参考与本篇既定方向？同篇强调色、字体角色、装饰方式是否突然变化？无意义英文、编号、标签能否去掉？
6. 完整性：原文与指定正文图均保留；无占位、编造引语、错误Logo或假二维码。对比最终HTML中实际保留的效果，不凭生成意图宣称成功。

记录具体可见问题及位置，例如“第二章图注与下段之间空隙过大”；合并修复最多一轮，修后最多再一次截图/看图。无明显问题就交付，不为了找问题任意换主题。局部文字更正可以复用上次有效检查；未能截图时执行结构检查并在 notes/交付中说明未做视觉验证。保留主入口工具与时间上限。

本清单只改变本篇文章，不批准发布、登录账号或修改 Bloop 前端。只有真实后台和手机预览才证明微信中的最终效果。
